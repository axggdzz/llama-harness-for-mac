# 统一异步日志管道设计（方案 A）

版本：v1.0　日期：2026-08-31　状态：已评审（含风险点修订）

## 1. 背景与目标

当前 `LogFile`（E-6 改造后）仍为半同步架构：调用方线程持 `_gate` 完成时间戳 + UTF8 编码 + Classify + Write；定时器 Flush 与轮切（close→rename→reopen，GB 级文件）也持同一把锁。推理期 llama-server 高频输出时，业务线程会被磁盘 I/O 卡住数毫秒。

**四个目标**：
1. 调用方零阻塞——Append/SlotAppend/DumpAppend 入队即返回（一次 lock + Enqueue，零编码、零分类、零磁盘）
2. 批量合并——一个 Flush 周期内多行合并写入，Write 系统调用次数降一个量级
3. 崩溃安全——最多丢一个 Flush 周期（≤150ms + ≤64KB），远优于现状"进程退出内存缓冲全丢"
4. 磁盘 I/O 降频——时间 + 大小双阈值 Flush

**覆盖范围**：四流统一——harness.log(2MB) / warn_error.log(5MB) / slot.log(2MB) / request_dump.log(2MB)。request_dump 当前由 SmartScheduler 在**请求路径上同步写盘**（L1520 `File.AppendAllText`），是顺带消掉的最大阻塞点。

## 2. 架构

```
┌─ 调用方（任意线程）──────────────────────────────┐
│ MainForm.AppendLog ──→ LogFile.Append           │
│ MainForm.OnSlotLog ──→ LogFile.SlotAppend       │
│ SmartScheduler dump ─→ LogFile.DumpAppend       │
└──────────────────┬──────────────────────────────┘
                   │ Enqueue(stream, createUtc, line)
                   │   lock 内仅：入队 + 满时丢弃计数 + _recent 更新
        ┌──────────▼──────────┐
        │  LogPipeline（新组件）│  全局单队列（50k 行，四流共享）
        │  单后台写线程          │
        └──────────┬──────────┘
                   │ 批量出队（≤150ms 或攒满 500 行）
        ┌──────────▼──────────┐
        │ 每流缓冲 + Flush 判定 │  时间 ≥150ms 或 字节 ≥64KB
        │ 轮切（close→rename） │  全在写线程内，调用方永不阻塞
        └──────────┬──────────┘
                   ▼
      harness.log / warn_error.log / slot.log / request_dump.log
```

**组件拆分**：
- **新文件 `LogPipeline.cs`**（~250 行）：管道核心——有界队列、单写线程、批量组装、双阈值 Flush、轮切编排、IO 退避、`[LOG-PIPE]` 埋点。
- **`LogFile.cs` 变薄门面**（~120 行）：Append/SlotAppend/DumpAppend/SnapshotRecent/Shutdown 全部转发管道；`Classify` 保留原位（已有测试覆盖）。
- **四流各自独立 `LogStreamWriter`**（复用现有类，移入管道内部），独立轮切互不干扰。

## 3. 消息实体与时间戳契约

```csharp
internal readonly struct LogMessage
{
    public LogStream Stream;        // Main / Warn(派生) / Slot / Dump
    public DateTime CreateUtc;      // Enqueue 时捕获 DateTime.UtcNow
    public string RawLine;          // 原始行（未加时间戳）
}
```

**契约（写入代码注释 + 架构文档）**：
- 单条日志流内部严格保序（FIFO）；跨流不做全局时间排序，落盘后文件间时间戳有微小错位——合理且可接受。
- **时间戳在 Enqueue 生产侧捕获**（`DateTime.UtcNow`），随消息入队，写线程只负责格式化输出——彻底消除"业务产生 A、B，A 排队 B 先消费 → 时间戳倒挂"的时序漂移。
- 输出格式不变：`[yyyy-MM-dd HH:mm:ss] {line}`（本地时间显示，Utc 值转换）。

## 4. 队列满策略（修订点 1）

```csharp
public enum QueueFullPolicy { DropOldest, DropNewest }
// AppConfig: LogQueueFullPolicy，默认 DropNewest
```

- **默认 DropNewest**：队列满时丢弃新入队日志，保留队列内已有历史——日志排查更看重最早的异常源头（如 KV 风暴中最早的错误堆栈），新消息丢几条可接受。
- `[LOG-PIPE] dropped_new=N`（累计计数，写线程消费时输出到 main 流）。
- 枚举可配置，写入 AppConfig + UI 配置页（下拉或复选，默认 DropNewest）。

## 5. `_recent` 环形缓冲（修订点 3）

**在生产侧 Enqueue 更新**（lock 内，与入队同锁）：
- `SnapshotRecent()` 行为与现状完全一致——UI 抓报错上下文不受写线程速度影响，无隐性行为变更。
- warn_error 上下文块仍为"该条之前 10 条"（含已入队未落盘行），与旧实现语义一致。
- **仅 main 流**入队时更新 `_recent`（与旧代码一致：SlotAppend/DumpAppend 从不参与 warn 上下文）；warn 流是派生输出不入 `_recent`。

## 6. Flush 双阈值与轮切

- **Flush 判定**（每流独立）：距上次 Flush ≥150ms **或** 缓冲字节 ≥64KB。
- **轮切边界**（修订点 6）：四流各自独立判断大小（main/slot/dump 2MB、warn 5MB），互不干扰；rename 失败继续写当前句柄不阻断（与现状一致）。
- 轮切全在写线程内执行，调用方永不感知。

## 7. IO 异常退避（修订点 5）

写线程 catch-all 后继续消费，但增加退避：
- 连续 3 次 IO 异常 → 间隔 200ms 再尝试（防磁盘满时死循环打满 CPU）。
- `[LOG-PIPE] io_fail=N`（累计失败计数埋点）。
- 单条消息 IO 失败不重试该条（尽力而为语义不变），仅计数 + 退避。

## 8. Shutdown 语义（修订点 4）

```
Shutdown() → 停止接收新入队 → drain 全部队列 → 最终 Flush → Dispose
Join 超时 3s
```

两种结果区分埋点：
- 正常 drain 完成：`[LOG-PIPE] shutdown drained N lines`
- 超时：`[LOG-PIPE] shutdown drain timeout, remain N lines lost`——明确告知丢失行数。

## 9. 内存与锁粒度（修订点 7/8）

- **全局单队列 50k 行**（四流共享，非每流 50k）：平均 200 字符/行 ≈ 10MB 上限，可控。
- **Enqueue lock 内仅**：入队、满时丢弃计数、`_recent` 更新。**绝对不做**格式化、IO、字符串拼接、Classify。

## 10. 埋点（约束 C-4）

`[LOG-PIPE]` 统一标记，可 grep：
| 事件 | 输出 |
|------|------|
| 管道启动 | `[LOG-PIPE] 启动：4 流，队列 50k，policy=DropNewest` |
| 队列满丢弃 | `[LOG-PIPE] dropped_new=N` |
| IO 失败 | `[LOG-PIPE] io_fail=N` |
| Shutdown drain | `drained N lines` / `drain timeout, remain N lines lost` |

## 11. 单元测试（13 项）

**原有 9 项**：
1. BoundedLineQueue：满时按 policy 丢弃 + 计数正确
2. BoundedLineQueue：FIFO 保序
3. FlushPolicy.ShouldFlush(elapsedMs, bufferedBytes)：双阈值边界（149ms/63KB 不刷、150ms/64KB 刷）
4. 轮切判定：达到阈值触发 rename；未达到不轮切
5. 轮切 `.1` 覆盖语义
6. Classify 回归（既有测试保持绿）
7-9. LogFile 门面转发行为

**追加 4 项**：
10. Enqueue 大量消息后 `SnapshotRecent()` 生产侧更新，不受写线程速度影响
11. 写线程 IO 异常：线程不退出、退避生效、io_fail 计数输出
12. Shutdown：正常 drain 全部输出；超时上报剩余行数
13. 高并发多线程 Enqueue：单流内部 FIFO 保序

## 12. 向后兼容与迁移约束

1. `LogFile.Append / SlotAppend / DumpAppend` 接口签名完全不变；**MainForm 零修改**。
2. 日志输出文本格式、时间戳格式、文件名完全不变——已有 grep/解析脚本无需改动。
3. 崩溃丢失窗口：从"进程退出内存缓冲全丢"→ 最多丢管道内未 drain 数据（≤150ms + ≤64KB），明确记录。
4. request_dump.log 内容格式不变（原始 body + headers），仅写入路径从 SmartScheduler 直接写盘改为管道。
