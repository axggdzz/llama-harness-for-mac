## 2. P0 高危缺陷（立即修复）

### P0-1 KV 快照文件名坍缩——所有 key 共用一个 .bin 文件

- **位置**：[KvCacheManager.cs:292](file:///c:/project/lunch/LlamaHarness/KvCacheManager.cs#L292)
- **现状**：

```csharp
return key.Where(c => !invalid.Contains(c) && c != '/' && c != '\\').ToString();
```

`Where()` 返回 `IEnumerable<char>`，对其调用 `ToString()` 得到的是**类型名字符串**（`System.Linq.Enumerable+...`），不是 key 内容。
- **后果**：所有 key 的快照文件名相同 → `dsh_agent_global.bin` 与 `trae_global.bin` 互相覆盖；restore 时加载到的是"最后一个 save 的会话"的 KV——**跨会话状态串扰，双槽 KV 复用核心功能在多 key 场景下整体失效**。
- **修复**（1 行）：

```csharp
return new string(key.Where(c => !invalid.Contains(c) && c != '/' && c != '\\').ToArray());
```

### P0-2 全槽强占排队场景空引用异常

- **位置**：[SlotAffinity.cs:133-140](file:///c:/project/lunch/LlamaHarness/SlotAffinity.cs#L133-L140)
- **现状**：

```csharp
var retry = _bindings.Where(kv => !kv.Value.Preemptive).OrderBy(...).FirstOrDefault();
if (retry.Key != "")   // FirstOrDefault 无匹配时 Key == null，null != "" 恒为 true
{
    ...
    _bindings.Remove(retry.Key);   // Remove(null) → ArgumentNullException
```

- **后果**：当全部槽位被强占绑定占满（AutoPreemptiveApps 前缀应用多开时完全可能），等待循环第 1 秒即抛 ArgumentNullException，请求失败；本意"安全起见"的兜底分支恰是崩溃源。
- **修复**：条件改 `retry.Key != null`（或将该兜底分支整体删除，直接依赖 30s 超时降级随机槽）。

### P0-3（语义）状态机四相的文档-实现冲突

- **文档**：Sleeping 是稳态待机（灰），"Sleeping 收到推理请求 → 触发唤醒"，另有 Stopped 态（红）。
- **实现**：枚举为 `{Standby, Waking, Running, Sleeping}`；**Sleeping 只是"休眠释放中"的瞬时过渡态（一切请求 502）**，真正的待机稳态是 Standby（推理请求经此唤醒）；StopNow 直接置 Standby；无独立 Stopped 态。
- **连带 UI 缺陷**：[MainForm.cs:1226](file:///c:/project/lunch/LlamaHarness/MainForm.cs#L1226) `Sleeping => Color.Red`——把瞬时过渡态显示为红色故障色，而文档语义中"休眠待机"应为灰色正常态。
- **修复建议**：以代码语义为准修订文档（Standby=待机稳态/Sleeping=释放过渡），UI 改 `Sleeping => DarkOrange`（过渡）、Standby => Gray；如需"已停止"红色标识，用 AutoMode=false 时状态文本区分而非独立枚举态。
