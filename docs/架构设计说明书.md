## 1. 项目概述

### 1.1 定位

LlamaHarness 是一个 Windows 桌面应用，为本地 llama.cpp 的 llama-server（OpenAI 兼容 LLM API 服务）提供：

1. **图形化启动器**：选模型、调参数、一键启停，实时日志；
2. **智能按需调度器**：常驻监听前端端口（默认 8080），首个推理请求触发唤醒，闲置 15 分钟自动休眠释放显存——"用即满血、闲即释放"；
3. **P 核亲和性管理**：Intel 混合架构 CPU（i5-13900F）上把 llama-server 绑定纯 P 核并自愈重绑；
4. **实时推理统计**：解析进程日志 print_timing 块，按请求展示输入/输出速度、投机解码命中率、f_sim_best、总耗时；
5. **双槽 KV 缓存复用**（v2.0）：多 agent 并发下按应用指纹固定槽位（n_slots 路由防跨槽漂移），驱逐/重启/截断/崩溃四个场景的 KV 快照 save/restore，主力会话自动冻结防驱逐，Tool 链会话锁定，前缀 HIT/MISS 可观测；
6. **思考模式拦截**（v2.0）：代理层识别"开启/关闭思考模式"及三档推理指令，注入 `chat_template_kwargs`（reasoning_effort + enable_thinking），全局状态机跨请求保持；
7. **TokenGuard + 输出续接**（v2.0）：真实分词计数防上下文超长 400，轮次制裁剪；finish_reason=length 自动续接（客户端无感），截断断点快照驻留；
8. **bad_alloc 崩溃自动恢复**（v2.0）：任务级内存耗尽时双源检测 → 三分支恢复（存活→KV 快照接续 / 进程死→重启重放 / 客户端断→不重放），SSE keep-alive 保活客户端无感续接，熔断器防无限循环。

### 1.2 技术选型

| 维度   | 选择                                 | 理由                                   |
| ------ | ------------------------------------ | -------------------------------------- |
| 运行时 | .NET 8（net8.0-windows）             | 目标框架，Windows 桌面                 |
| UI     | WinForms                             | 功能边界小，避免 WPF/AvalonUI 过度设计 |
| 依赖   | **零第三方 NuGet 包**                | 单项目自包含，降低供应链与维护成本     |
| HTTP   | System.Net.HttpListener + HttpClient | BCL 内置，监听本机回环无需管理员权限   |
| 配置   | System.Text.Json                     | BCL 内置                               |

### 1.3 部署形态

- 单 exe（Llama-harness.exe），同目录运行时生成：
  - config.json —— 用户配置（含本机模型/exe 路径，不入库）；
  - slot_bindings.json —— 槽位亲和绑定表（key→slot/强占/KV缓存开关，持久化）；
  - harness.log / harness.log.1 —— 主日志（2MB 轮切）；
  - warn_error.log —— 警告/错误独立日志（5MB 轮切，带上下文）；
  - slot.log —— 槽位事件独立日志（绑定/驱逐/KV save/restore，2MB 轮切）；
  - request_dump.log —— 请求体 dump（应用识别分析用，body 截断 2000 字符）；
  - unhandled.log —— 崩溃兜底日志。
- KV 快照 .bin 文件落盘至 KvCachePath（默认 `g:/temp`，SSD RAMDisk）。
- 目标硬件环境：Intel i5-13900F（8 P 核 + E 核混合架构）、NVIDIA GPU、本地 27B GGUF 模型（Qwen3.8-27B-Ridge）。

## 3. 核心模块设计

### 3.1 Program —— 入口与兜底

启动顺序：

1. Application.SetHighDpiMode(PerMonitorV2)（必须在创建任何窗口之前）；
2. **单实例守卫**：命名 Mutex "Local\LlamaHarness"，已存在则弹框退出——防止两个实例同时唤醒 llama-server 导致显存双倍占用；
3. EnableVisualStyles + SetCompatibleTextRenderingDefault(false) + SetUnhandledExceptionMode(CatchException)（UI 线程异常捕获并提示）；
4. AppDomain.UnhandledException 处理器（后台线程异常写 unhandled.log）；
5. Application.Run(new MainForm())，外层 try/catch 兜底。

**阶段状态机**（由 SmartScheduler.PhaseChanged 事件驱动）：

| 阶段     | 显示       | 颜色 | 触发条件                          |
| -------- | ---------- | ---- | --------------------------------- |
| Sleeping | 休眠中     | 灰   | 无 llama-server 进程，监听常驻     |
| WakingUp | 唤醒中...  | 黄   | 首个推理请求触发 WakeUpAsync      |
| Running  | 运行中     | 绿   | 后端就绪，开始代理转发            |
| Stopped  | 已停止     | 红   | 用户点击停止                      |

**关键 UI 机制**：

1. **日志防抖队列**：`_logQueue` + `_logFlushTimer`（150ms）——后台日志事件先入队，定时器批量追加到 RichTextBox，避免高频跨线程 Invoke 导致 UI 卡顿；按级别着色（INFO/DEBUG/WARN/ERROR）。
2. **崩溃告警**：`OnMetricsTick` 每 2s 轮询 `CrashRecovery.IsTripped` → 熔断时状态栏变红 + 醒目日志（`_crashAlertShown` 防重复告警）；窗口滑出后自动恢复。
3. **事件编组**：所有后台线程事件（Log / PhaseChanged / RoundUpdated / ThinkingModeChanged）经 `BeginInvoke` 编组到 UI 线程。
4. **统计 DataGridView**（8 列）：task ID、输入速度、输出速度、投机解码命中率、f_sim_best、总耗时等，数据源为 LlamaStatsParser 环形队列。
5. **槽位管理页**：DataGridView 可直接编辑 Preemptive/KVCacheEnabled，变更立即持久化到 slot_bindings.json。
6. **配置管理页**：AddRow 模式参数面板，保存走原子写（tmp+rename），载入重新加载。

### 3.3 SmartScheduler —— 调度核心与代理网关

项目最大模块（1407 行），承载全部非 UI 逻辑：监听代理、唤醒/休眠、亲和性自愈、思考模式状态机、KV 复用编排、崩溃恢复管道。

**阶段状态机**：

```text
Stopped ──LaunchNowAsync──▶ WakingUp ──WaitReady ok──▶ Running
   ▲                          │                          │
   │                          │ WaitReady fail           │ 闲置超时 / StopNow
   └──────────────────────────┘                          ▼
                                              Sleeping ◀── SleepNow
                                                   │
                              推理请求到达 ────────┘（WakeUpAsync 回到 WakingUp）
```

**AcceptLoop 与请求分类**：

- `HttpListener` 双前缀常驻监听（`http://localhost:8080/` + `http://127.0.0.1:8080/`）；
- C-008：accept loop 运行期异常重试（连续 3 次失败 → RaiseStatus "监听失败"）；
- `HandleRequestAsync` 分类处理：
  - `GET /__status__` → JSON `{phase, inflight, backend_port, idle_minutes, slots:{count,bindings}, recent_logs}`（C-103）；
  - Sleeping 阶段收到推理请求 → 触发唤醒后转发；
  - 探测类请求（无唤醒权，如健康检查）→ 503；
  - 推理请求 → inflight++（`_inflightPeak` 记录峰值，C-102）→ 必要时 WakeUp → ForwardAsync；
  - try/finally 保证 inflight--（C-002）。

**唤醒流程**（`WakeUpAsync`）：

1. `StatsReset?.Invoke()`（C-007：唤醒前清空旧轮统计，防跨轮污染）；
2. 唤醒计数 / 耗时统计（C-102）；
3. `LlamaFinder.BuildArgs` 拼接命令行；
4. `LlamaServerProcess.Start` 静默拉起；
5. `WaitReadyAsync`：探测后端端口（前端端口 +1 起），C-003 校验响应 body 含 `"object":"list"`（防其他服务误判就绪），每 15s 输出进度日志；
6. 成功后创建 SlotAffinity / KvCacheManager 实例（幂等）。

**ForwardAsync 全管道**（顺序执行）：

```text
客户端请求
  │
  ├─① 思考模式拦截："开启/关闭思考模式"或三档推理指令 → 状态机迁移 + 返回确认（不转发后端）
  │
  ├─② 槽位亲和：GetSlot(req.Headers, autoPreemptive)
  │     └─ Tool 链锁定：末条消息 role=tool → SetPreemptive(true) [KV-LOCK]；
  │        只解锁自己锁的键（_toolLockedKeys）[KV-UNLOCK]
  │
  ├─③ rebinding restore：槽位变更且旧槽有快照 → [KV-RESTORE] + 前缀哈希基线重置
  │
  ├─④ TokenGuard.GuardAsync：真实分词计数，超长轮次制裁裁剪（防 400）
  │
  ├─⑤ LogPrefixHash：SHA256(最新一轮之前的 messages JSON) → [KV-HIT]/[KV-MISS]
  │
  ├─⑥ OutputContinuer.HandleStreamAsync：SSE 管道 + 截断续接（onTrunc 闭包 → save 断点快照）
  │
  ├─⑦ TryCrashRecoverAsync：bad_alloc 检测 → 三分支恢复
  │
  └─⑧ §6.3 清理：completed && wasPending → DeleteCache + [KV-CLEANUP]
```

**强制流式**（`EnsureStreamTrue`）：C-005 DOM 优先解析 + 字符串降级替换，失败时透传原请求。

**闲置休眠**（`SleepNow`）：闲置定时器（IdleMinutes，默认 15min）触发；Kill 进程树；休眠计数统计（C-102）；`VerifyVramReleasedAsync`（C-006：3s 后查显存，未回落则告警）。

**P 核自愈**：唤醒后及周期性 `CpuAffinity.Heal` 重绑 P 核掩码（防 E 核漂移）。

**思考模式状态机**：

- `ThinkingLevel {Off / Low / Medium / XHigh}`；
- `DetermineInitialThinkingMode(extraArgs)`：enable_thinking:true→XHigh / false→Off / 未指定→XHigh；
- `InjectThinkingMode(json, ref level, out effortFix)`：注入 `chat_template_kwargs`（reasoning_effort + enable_thinking）；
- `_thinkingGate` 锁保护状态迁移，`ThinkingModeChanged` 事件驱动 UI 底部面板显示。

**崩溃恢复管道**（详见 §4.6）：

- `TryCrashRecoverAsync`：CrashRecovery 双源检测（进程退出码 + 日志 bad_alloc 关键字）；
- `RecoverAliveAsync`：SSE keep-alive（`: keepalive\n` 每 5s）+ writeGate 写门控 + ProbeClientConnectedAsync + save n_saved>0 + freeGb<4 → budget*0.75 + 快照接续或全量重放；
- `RestartAndReplayAsync`：≤MaxAutoRestarts 次 EnsureRunningAsync + URI 重建 + 严格预算；
- 熔断器：10min ≥3 次 → IsTripped（UI 红色告警）。

### 3.4 LlamaServerProcess —— 子进程封装

- 封装 llama-server.exe 的启动/停止：`Start(args)` 静默运行（无窗口）、`OutputLine` 事件逐行回调、`Kill()` 杀整个进程树；
- 退出码与异常退出通过事件上报给 SmartScheduler（崩溃恢复双源检测之一）；
- 输出重定向到内存缓冲，供 LlamaStatsParser 解析 + LogFile 落盘。

### 3.5 AppConfig —— 配置模型

config.json 原子读写（tmp+rename），Load() 数值兜底（非法值回退默认）。完整字段：

| 字段                        | 默认值                          | 说明                                  |
| --------------------------- | ------------------------------- | ------------------------------------- |
| SchemaVersion               | 1                               | schema 版本号（C-004 前向兼容）       |
| ExePath / ModelPath         | ""                              | llama-server.exe / GGUF 模型路径      |

### 3.6 LlamaFinder —— exe 定位与命令行拼接

- exe 三级定位：配置路径 → 同目录 → PATH；
- `BuildArgs` 模板：

```text
-m "<model>" --port <p> -c <ctx> -ngl <ngl> --parallel <np>
  [--slots --slot-save-path <path>]      # 仅 Parallel>1 && KvCachePath 非空
  [--no-kv-unified] -t <threads> [ExtraArgs]
```

- `--slots` 端点是 KV 快照 save/restore 的前提（llama-server 侧槽位持久化接口）。

### 3.7 CpuAffinity —— P 核亲和性

- 解析 P 核掩码（默认 0x0000FFFF = 低 8 个 P 核）；
- `Apply(pid)`：SetProcessAffinity 绑定；
- `Heal(pid, expectedMask)`：读回实际亲和性，漂移则重绑（自愈）。

### 3.8 LlamaStatsParser —— print_timing 实时解析

- 正则解析 llama-server 日志中的 print_timing 块；
- 按 task ID 归组为一轮（Round）：输入/输出 token 数、速度、投机解码命中率、f_sim_best、总耗时；
- 50 轮环形淘汰（防内存无限增长）；
- `Feed(line)` 来自进程输出线程，`Reset()` 由调度器在唤醒前调用（C-007），内部锁串行化。

### 3.9 LogFile —— 日志文件

- 主日志 harness.log（2MB 轮切 → harness.log.1）；
- **分级独立输出**：warn_error.log（5MB 轮切，带上下文行）——警告/错误单独成文便于排查；
- **slot.log**：槽位事件独立日志（绑定/驱逐/KV save/restore，2MB 轮切），UI 槽位绑定页直接展示；
- `Classify` 三级分类：中文关键字 → IWE 严重度正则 → 英文关键字；
- C-001：`_recent` 环形队列全部操作在 `lock(_gate)` 内（recent_logs 端点数据源）；
- 静态类，尽力而为（写失败不抛异常，不影响主流程）。

### 3.10 SystemMetrics —— 资源采样

- 后台 Task 每 2s 轮询：CPU 利用率、内存占用、GPU 显存（nvidia-smi）；
- `nvidia-smi` 调用带 WaitForExit 超时（C-009：防进程挂起阻塞采样线程）；
- 只读采样，不参与任何决策（决策由 SmartScheduler 基于事件驱动）。

### 3.11 SlotAffinity —— 应用指纹 → 槽位绑定

- **应用指纹**：从请求头/body 提取应用标识（如 dsh_agent_global / trae_global）；
- **GetSlot(headers, autoPreemptive)**：指纹查 slot_bindings.json 绑定表，未命中则分配空闲槽位并持久化；
- **LRU 驱逐**：槽位满时驱逐最久未使用的非强占绑定；
- **强占冻结**（Preemptive=true）：暂停 LRU 驱逐（§4.2 自动强占 + §4.5 Tool 链锁定共用此机制）；
- **自动强占**：AutoPreemptiveApps 前缀匹配 → 绑定强制 Preemptive=true；
- **Tool 链锁定**：messages 末条 role=tool → agent 工具循环进行中 → SetPreemptive(true) [KV-LOCK]；只解锁自己锁的键（_toolLockedKeys）[KV-UNLOCK]；
- 内部锁保护并发访问。

### 3.12 KvCacheManager —— KV 快照 save/restore

- **索引**：key→{slot, token_count, size} 内存索引 + slot_bindings.json 持久化；
- **SaveAsync(key, slot)**：POST /slots/{id}?action=save → llama-server 落盘 .bin 到 KvCachePath；
- **RestoreAsync(key, slot)**：POST /slots/{id}?action=restore → 加载 .bin 恢复 KV；
- **DeleteCache(key)**：删除 .bin + 清索引（§6.3 续接成功后清理过期快照）；
- **四场景**：驱逐前 save / rebinding restore / 截断断点 save / 崩溃恢复 save+restore；
- 内部锁保护并发访问。

### 3.13 TokenGuard —— 上下文防护

- **真实分词计数**：调用后端 tokenize 端点统计 messages 实际 token 数（非字符估算）；
- **轮次制裁剪**：超限时从最旧轮次开始裁剪（保留 system + 最近 N 轮），防 400；
- **内容兜底截断**：单条消息超长时截断内容（保留头尾）；
- `GuardAsync(request, budget)` → 返回裁剪后的请求 + 裁剪日志。

### 3.14 OutputContinuer —— SSE 管道与截断续接

- **HandleStreamAsync**：代理转发 + SSE 流式直通（逐 chunk 转发客户端）；
- **截断续接**：finish_reason=length → onTrunc 回调（save 断点快照）→ 自动续接（追加"继续"指令重放），客户端无感；
- **工具隔离**：续接请求剥离 tool_calls（防工具调用重复触发）；
- **写门控**：`writeGate`（SemaphoreSlim）保证 SSE 写入串行化（keep-alive 与数据帧不交错）；
- **MaxContinuations**：单请求最大续接次数（默认 10），超限停止并告警。

### 3.15 CrashRecovery —— bad_alloc 检测与熔断

- **双源检测**：进程退出码（非 0）+ 日志 bad_alloc 关键字，任一命中即判定崩溃；
- **RecordCrash(ts)**：记录崩溃时间戳；
- **熔断器**：10min 窗口内 ≥3 次 → IsTripped=true（UI 红色告警 + 停止自动恢复）；
- **IsTripped**：只读属性，UI 每 2s 轮询；
- 静态类，内部锁保护时间戳队列。

## 4. 关键流程

### 4.1 启动流程

```text
Program.Main
  ├─ SetHighDpiMode(PerMonitorV2)
  ├─ 单实例 Mutex "Local\LlamaHarness"（已存在 → 弹框退出）
  ├─ EnableVisualStyles + UnhandledException 处理器
  └─ Application.Run(new MainForm())
       ├─ Load AppConfig（config.json，数值兜底）
       ├─ 初始化 SmartScheduler（HttpListener 双前缀监听 :8080）
       ├─ AcceptLoopAsync 启动（异常重试 3 次）
       └─ 阶段 = Sleeping（常驻监听，无 llama-server 进程）
```

### 4.2 稳态循环（Sleeping ↔ Running）

```text
Sleeping ──推理请求──▶ WakeUpAsync ──WaitReady ok──▶ Running
   ▲                                                           │
   │            闲置 IdleMinutes（默认 15min）                 │
   └──────────────── SleepNow（Kill 进程树 + VerifyVramReleased）
```

- 唤醒：StatsReset → BuildArgs → Start → WaitReady（探测 + body 校验）→ CpuAffinity.Apply；
- 休眠：闲置定时器触发 → Kill → 3s 后查显存确认回落（C-006）。

### 4.3 单请求全管道（ForwardAsync）

见 §3.3 ForwardAsync 全管道图（8 步顺序执行）。关键约束：

- **思考模式拦截**优先于一切（纯网关侧处理，不触达后端）；
- **槽位亲和**在转发前确定（决定 --slots 路由 + KV 快照归属）；
- **TokenGuard** 在转发前裁剪（防 400）；
- **崩溃恢复**在 SSE 管道内检测（流中断时介入）；
- **§6.3 清理**最后执行（续接成功后删过期快照）。

### 4.4 KV 复用七场景

| # | 场景 | 触发条件 | 动作 | 标记 |
| - | ---- | -------- | ---- | ---- |
| §4.1 | 截断断点驻留 | finish_reason=length | onTrunc → save 快照 → 标记「截断待续接」→ 续接成功清理 / 失败保留 | [KV-SAVE] [KV-CLEANUP] |
| §4.2 | 空闲冻结防驱逐 | AutoPreemptiveApps 前缀匹配 | 绑定强制 Preemptive=true（暂停 LRU） | — |
| §4.3 | 重启自愈快照 | 进程重启后首请求 | rebinding restore（旧槽快照加载到新槽） | [KV-RESTORE] |
| §4.4 | TokenGuard 裁剪前缀增量 | 裁剪后 messages 变化 | 前缀哈希重置基线（防误报 MISS） | [KV-HIT]/[KV-MISS] |
| §4.5 | Tool 链锁定 | 末条消息 role=tool | SetPreemptive(true)；只解锁自己锁的键 | [KV-LOCK] [KV-UNLOCK] |
| §4.6 | 微调 Prompt 增量 | 用户修改 system prompt | 前缀哈希 HIT/MISS 判定（SHA256 最新一轮之前） | [KV-HIT]/[KV-MISS] |
| §4.7 | 双槽亲和防漂移 | 多 agent 并发 | GetSlot 固定槽位（n_slots 路由） | — |

**可观测统一标记**：`[KV-HIT]` / `[KV-MISS]` / `[KV-SAVE]` / `[KV-RESTORE]` / `[KV-CLEANUP]` / `[KV-LOCK]` / `[KV-UNLOCK]`，写入 slot.log + UI 日志。

### 4.5 日志数据流

```text
llama-server stdout ──OutputLine──▶ SmartScheduler
                                      ├─▶ LlamaStatsParser.Feed（print_timing 解析）
                                      ├─▶ LogFile（harness.log / warn_error.log）
                                      └─▶ CrashRecovery.OnBackendLine（bad_alloc 检测）

SmartScheduler 内部事件 ──Log 事件──▶ MainForm（BeginInvoke → _logQueue → 150ms 防抖 → RichTextBox）
SlotAffinity/KvCacheManager 事件 ──▶ LogFile.SlotAppend（slot.log）+ UI 槽位绑定页
```

### 4.6 崩溃恢复三分支

```text
TryCrashRecoverAsync（SSE 管道内检测）
  │
  ├─ 分支 A：进程存活（bad_alloc 但进程未死）
  │    └─ RecoverAliveAsync
  │         ├─ SSE keep-alive（`: keepalive\n` 每 5s，writeGate 门控）
  │         ├─ ProbeClientConnectedAsync（客户端是否还连着）
  │         ├─ save n_saved>0（快照已落盘）
  │         ├─ freeGb<4 → budget*0.75（显存紧张降预算）
  │         └─ 快照接续（restore + 从断点续推）或全量重放
  │
  ├─ 分支 B：进程死亡
  │    └─ RestartAndReplayAsync
  │         ├─ ≤MaxAutoRestarts 次 EnsureRunningAsync
  │         ├─ URI 重建（后端端口可能变化）
  │         └─ 严格预算重放（ReservedOutputTokens）
  │
  └─ 分支 C：客户端断开
       └─ 不重放（直接清理，释放资源）
```

**熔断器**：10min ≥3 次 → IsTripped（UI 红色告警 + 停止自动恢复，需人工介入）。

### 4.7 配置数据流

```text
UI 配置管理页 ──Save──▶ AppConfig.Save（tmp+rename 原子写）──▶ config.json
config.json ──Load──▶ AppConfig.Load（数值兜底）──▶ SmartScheduler 运行时参数
slot_bindings.json ◀──▶ SlotAffinity/KvCacheManager（绑定表持久化）
```

## 5. 线程并发模型

| 线程/上下文        | 职责                                   | 同步机制                          |
| ------------------ | -------------------------------------- | --------------------------------- |
| UI 主线程（STA）   | MainForm 全部控件操作                  | BeginInvoke 编组后台事件          |
| Accept loop 线程   | HttpListener.AcceptAsync + 请求分发    | 异常重试 3 次（C-008）            |
| 请求处理线程       | HandleRequestAsync / ForwardAsync      | inflight++/-- (try/finally, C-002) |
| 进程 IO 线程       | llama-server stdout 逐行回调           | LlamaStatsParser 内部锁           |
| 后台采样 Task      | SystemMetrics 每 2s 轮询               | nvidia-smi WaitForExit 超时（C-009）|
| 定时器线程         | 闲置休眠 / P 核自愈 / UI metrics tick  | 阶段状态机原子迁移                |

**关键锁**：

| 锁                 | 保护对象                          | 所在模块          |
| ------------------ | --------------------------------- | ----------------- |
| `_kvStateGate`     | _truncPending / _toolLockedKeys / _prefixHashes | SmartScheduler    |
| `writeGate`        | SSE 写入串行化（keep-alive 与数据帧不交错） | OutputContinuer   |
| `_thinkingGate`    | 思考模式状态机迁移                | SmartScheduler    |
| `_dumpLock`        | request_dump.log 写入             | SmartScheduler    |
| `lock(_gate)`      | LogFile._recent 环形队列（C-001） | LogFile           |
| 内部锁              | SlotAffinity / KvCacheManager / CrashRecovery 各自状态 | 各模块           |

**死锁规避原则**：跨模块调用不持锁（如 ForwardAsync 中 GetSlot → SaveAsync 顺序调用，不嵌套持锁）。

## 7. 设计决策

| #   | 决策                          | 理由 / 备选否决原因                                  |
| --- | ----------------------------- | ---------------------------------------------------- |
| D1  | 前端端口常驻 + 后端动态端口   | 客户端对接地址恒定；唤醒/休眠透明。备选：固定后端端口 → 端口冲突风险 |
| D2  | HttpListener 而非 ASP.NET Core | 零依赖、单进程、本机回环无需管理员权限               |
| D3  | SSE 直通 + 网关拦截           | 流式低延迟；网关只拦截必要字段（思考模式/TokenGuard）|
| D4  | P 核掩码硬编码默认值          | i5-13900F 固定硬件；配置可覆盖                       |
| D5  | print_timing 正则解析         | llama-server 无独立统计 API；日志是唯一数据源        |
| D6  | 双槽 KV 复用（n_slots 路由）  | 多 agent 并发防跨槽漂移；单槽无法隔离               |
| D7  | KV 快照四场景（驱逐/重绑/截断/崩溃） | 全生命周期覆盖；.bin 落盘 RAMDisk 防重启丢失     |
| D8  | Tool 链末条判定               | 历史残留 tool 消息会永久误锁；末条 role=tool 才表示工具循环进行中 |
| D9  | 前缀哈希可观测                | SHA256(最新一轮之前 messages) → HIT/MISS 判定；restore 后重置基线防误报 |
| D10 | 思考模式状态机（全局跨请求）   | chat_template_kwargs 注入；_thinkingGate 锁保护迁移  |
| D11 | bad_alloc 三分支恢复          | 存活→快照接续 / 进程死→重启重放 / 客户端断→不重放    |
| D12 | SSE keep-alive + writeGate    | 崩溃恢复期间保活客户端无感；写门控防帧交错           |
| D13 | 熔断器（10min ≥3 次）         | 防无限重启循环；IsTripped 需人工介入                 |
| D14 | 零第三方 NuGet 包             | BCL 内置 HttpListener/HttpClient/System.Text.Json 够用 |
| D15 | WinForms 而非 WPF/AvalonUI    | 功能边界小，避免过度设计                             |

## 8. 错误自愈矩阵

| 故障场景                | 检测方式                          | 自愈动作                              | 人工介入条件          |
| ----------------------- | --------------------------------- | ------------------------------------- | --------------------- |
| llama-server 启动失败    | WaitReadyAsync 超时               | 重试（≤3 次）→ 阶段回 Sleeping        | 连续失败              |
| 后端端口被占用           | 探测失败                          | 自动 +1 换端口                        | 端口耗尽              |
| P 核漂移                 | CpuAffinity.Heal 读回比对         | 重绑 P 核掩码                         | —                     |
| 显存未回落（休眠后）     | VerifyVramReleasedAsync（C-006）  | 告警日志                              | 反复出现              |
| 上下文超长 400           | TokenGuard 真实分词计数           | 轮次制裁剪 + 内容兜底截断             | —                     |
| 输出截断（finish_reason=length） | SSE 流检测                  | 自动续接（≤MaxContinuations）+ 断点快照 | 续接超限              |
| bad_alloc（进程存活）    | CrashRecovery 双源检测            | RecoverAliveAsync（keep-alive + 快照接续/重放） | 熔断触发          |
| bad_alloc（进程死亡）    | 进程退出码非 0                    | RestartAndReplayAsync（≤MaxAutoRestarts） | 重启超限 / 熔断     |
| 客户端断开               | ProbeClientConnectedAsync         | 不重放，清理资源                      | —                     |
| KV restore 失败          | RestoreAsync 异常                 | 降级为全量重放                        | —                     |
| HttpListener accept 异常 | AcceptLoop 捕获                 | 重试 3 次 → RaiseStatus "监听失败"    | 连续失败              |
| nvidia-smi 挂起          | WaitForExit 超时（C-009）         | 跳过本轮采样                          | —                     |
| config.json 损坏         | Load() 反序列化异常               | 数值兜底 + 回退默认                   | —                     |
| UI 线程异常              | SetUnhandledExceptionMode         | 弹框提示 + unhandled.log              | —                     |
| 后台线程异常             | AppDomain.UnhandledException      | unhandled.log                         | —                     |

## 附录 A —— 黄金命令行

llama-server 实际启动命令（Parallel=2、KvCachePath=g:/temp 示例）：

```text
llama-server.exe -m "g:\models\Qwen3.8-27B-Ridge.gguf" --port 8081 -c 262144 -ngl 999 --parallel 2 --slots --slot-save-path g:/temp --no-kv-unified -t 8
```

- `--slots --slot-save-path`：KV 快照端点前提（仅 Parallel>1 && KvCachePath 非空时拼接）；
- `--port`：后端端口（前端 +1 探测结果），非固定 8080；
- `-t 8`：P 核线程数（CpuAffinity 绑定后）。

## 附录 B —— 术语表

| 术语 | 含义 |
| ---- | ---- |
| 槽位亲和（Slot Affinity） | 应用指纹 → 固定槽位绑定，防多 agent 并发跨槽漂移 |
| 强占（Preemptive） | 暂停 LRU 驱逐的绑定标记（自动强占 / Tool 链锁定共用） |
| 断点快照 | finish_reason=length 时 save 的 KV .bin，续接失败保留供 rebinding/崩溃恢复 restore |
| keep-alive | SSE 保活帧（`: keepalive\n`），崩溃恢复期间维持客户端连接 |
| 熔断器（Circuit Breaker） | 10min ≥3 次崩溃 → IsTripped，停止自动恢复需人工介入 |
| 前缀哈希 | SHA256(最新一轮之前的 messages JSON)，KV HIT/MISS 可观测判定 |
| writeGate | SemaphoreSlim 写门控，SSE 写入串行化（keep-alive 与数据帧不交错） |
| n_slots 路由 | llama-server --parallel>1 时的槽位路由机制，KV 快照按槽隔离 |
| print_timing | llama-server 日志中的推理统计块（task ID / 速度 / 投机命中率等） |
| P 核亲和 | Intel 混合架构 CPU 上把 llama-server 绑定纯 P 核（防 E 核漂移） |
| 轮次制裁剪 | TokenGuard 超限时从最旧轮次开始裁剪（保留 system + 最近 N 轮） |
| rebinding restore | 槽位变更后从旧槽快照加载 KV 到新槽（重启自愈场景） |
