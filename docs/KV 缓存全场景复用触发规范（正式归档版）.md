## 2\. 基础概念定义

### 2\.1 被动复用（llama\.cpp 原生）

框架默认行为：槽位未释放、未驱逐、上下文前缀未变更时，自动复用已有 KV 缓存。特点：无需上层干预，但生命周期短、极易被冲刷、截断后直接失效。

### 2\.2 主动复用（Harness 自研增强）

上层调度主动管控 KV 生命周期：驻留、冻结、快照、恢复、前缀增量匹配、防驱逐。特点：可控、稳定、适配长会话、彻底消灭无效重算。

### 2\.3 缓存失效判定标准

满足任意一条即判定为不可复用，需重新全量 Prefill：

- 会话槽位被 LRU 驱逐、主动释放

- 上下文前缀发生修改、插入、删除旧轮核心内容

- system 提示词发生变更

- 超限裁剪后上下文结构不匹配

- 服务重启、槽位重置、缓存快照损坏

## 3\. 原生被动复用场景（基础保底规则）

以下为 llama\.cpp 原生自带复用逻辑，作为体系保底能力，无需上层干预。

### 3\.1 同会话连续多轮对话复用

**触发条件**：同一 SessionID 绑定同一槽位，无驱逐、无释放、无前缀变更。

**行为**：历史 KV 完全复用，仅对最新一轮消息做增量 Prefill \+ Decode。

**约束**：会话空闲超时、槽位抢占、上下文变更会立即失效。

### 3\.2 槽位常驻未过期复用

**触发条件**：槽位未达 LRU 淘汰时间、未被新会话抢占。

**行为**：缓存持续驻留，反复命中，大幅降低连续提问耗时。

**短板**：普通会话与主力长会话无差别优先级，长会话易被新会话挤掉缓存。

## 4\. 自研主动高收益复用场景（核心提效、正式归档标准）

本章节为稠密优化 M1/M2 收官核心能力，是区别于原生开源部署的关键技术壁垒，所有场景强制落地执行。

### 4\.1 输出截断断点驻留复用（最高优先级、最大收益）

**触发时机**：推理结束返回 `finish_reason=length`（输出超长截断）

**原生缺陷**：截断后立即 release 槽位、冲刷 KV，下次继续必须全量重算（10s\+ 耗时）。

**规范触发行为**：

1. 检测到截断后 **禁止立即冲刷 KV**

2. 抢占时序在槽位释放前执行 **断点 KV 快照 save** 存入 RAMDisk

3. 标记会话为「截断待续接状态」，锁定现场不销毁

4. 下次同会话续接请求，优先 restore 截断点 KV，**零全量重算、仅增量解码**

**适用场景**：长代码生成、长文档续写、超长输出被截断的所有场景。

### 4\.2 主力会话空闲冻结防驱逐复用

**触发时机**：长会话进入短暂空闲、无新请求，但业务判定为活跃会话。

**原生缺陷**：空闲几秒即被 LRU 驱逐，KV 丢失，再次提问需要全量重算。

**规范触发行为**：

1. 按业务 Key 识别主力长会话、编码会话、Agent 持续会话

2. 对判定为核心业务的会话，**冻结槽位、暂停 LRU 计时**

3. 空闲期持续保留 KV 缓存，不被新会话抢占

4. 用户再次交互直接复用完整缓存，零 Prefill 开销

**收益**：彻底解决“停顿一会就变慢、重新加载上下文”的体验问题。

### 4\.3 服务重启/故障自愈快照复用

**触发时机**：服务重启、进程重启、BadAlloc 任务级异常自愈完成后。

**原生缺陷**：重启全量清空，所有会话强制从头重算。

**规范触发行为**：

1. 启动后自动扫描有效 RAMDisk 快照

2. 会话重连时优先 restore 历史 KV 状态

3. 自愈恢复前强制资源余量校验，避免快照 OOM 反噬

4. 恢复成功直接接续会话，无需用户重试、无需全量重算

### 4\.4 TokenGuard 裁剪后前缀增量复用

**触发时机**：超长上下文触发 TokenGuard 轮次裁剪，删除最旧历史、保留 system\+最新轮次。

**规范触发行为**：

1. 裁剪后校验上下文前缀一致性

2. 前缀未变更部分 **复用原有 KV**

3. 仅对删除差异、新增内容做增量 Prefill

4. 避免裁剪后整包重算的巨大性能浪费

**约束**：最小保留集发生结构性变更时，放弃增量复用，安全全量刷新。

### 4\.5 Tool 工具链连续会话锁定复用

**触发时机**：连续 tool\_call / tool\_result 多轮交互的 Agent 会话。

**原生缺陷**：多轮工具来回迭代，频繁重检完整上下文，耗时极高。

**规范触发行为**：

1. 识别完整工具配对会话，标记为「工具链持续会话」

2. 锁定槽位不驱逐、不刷新、不抢占

3. 连续工具迭代全程复用 KV 缓存

4. 工具会话结束后解除锁定，恢复常规 LRU 策略

### 4\.6 小幅微调 Prompt 增量复用

**触发时机**：用户仅小幅追加、微调结尾指令，上下文前缀完全不变。

**规范触发行为**：复用前缀全部 KV，仅增量计算尾部变更内容，最大化节省 Prefill 耗时。

### 4\.7 双槽位亲和绑定防漂移复用

**触发时机**：长会话全程绑定固定槽位。

**规范触发行为**：

1. 按业务 Key 固定亲和槽位，禁止会话跨槽漂移

2. 彻底杜绝槽位切换导致的 KV 全盘失效重建

3. 双槽各司其职，缓存命中率长期稳定拉满

## 5\. KV 缓存失效 \& 强制刷新规范（禁止盲目复用场景）

以下场景**禁止强制复用**，必须刷新缓存、重新 Prefill，保证语义正确与资源安全：

- System 系统提示词发生修改、替换

- 历史消息中间存在插入、删除、篡改操作

- TokenGuard 裁剪后上下文前缀结构不匹配

- 快照损坏、快照版本不匹配、快照不完整

- 资源余量不足，复用快照会触发 OOM / bad\_alloc

- 检测到会话内容重复死循环，需要强制刷新状态

## 6\. 缓存生命周期管控标准

### 6\.1 常规临时会话

LRU 常规淘汰、超时自动释放、快照短期留存、自动清理垃圾。

### 6\.2 主力长会话 / 编码 / Agent 会话

常驻冻结、禁止主动驱逐、截断必快照、重启可恢复、手动干预才释放。

### 6\.3 截断待续接会话

快照长期留存、优先恢复、续接成功后自动清理过期快照。

## 7\. 资源风控联动规则（稳态底线）

所有 KV 复用行为必须服从 **前置静态资源预算 \+ 动态显存双阈值**：

- 缓存复用不得突破单槽物理显存上限（339MB 现场硬阈值）

- 复用前校验资源余量，余量不足优先 TokenGuard 裁剪，再执行复用

- 杜绝超大超限快照强行恢复导致的二次 OOM

- 杜绝运行态极限资源压榨，缓存收益让位于系统稳态
