# 四、槽位绑定策略（核心 KV 优化逻辑）

## 1. 绑定原则（最重要）

- **第一次请求随机分配空闲槽**
- **绑定后永久锁死该槽**
- **无论空闲、繁忙、多次对话，绝不换槽**
- **亲和槽忙 → 等待 / 重试，禁止漂移**

## 2. 双槽分配策略

- Slot0 / Slot1 两个常驻推理实例
- 每个 **业务 / 会话 key** 固定独占一个槽
- 不同业务自动分流到固定槽，**互不抢占 KV**

### 最终效果（你想要的完美状态）

- Trae 永远跑在 slot0
- WebUI 所有会话固定各自槽
- DSH 规则引擎用户各自独占槽
- DSH 主 Agent 固定另一槽
  **彻底解决跨槽重建 KV、互相冲刷缓存问题**

# 五、代理层完整识别 + 自动绑定代码（可直接落地）

我给你 **可直接塞进 llama-harness** 的完整识别器 + 亲和算法

```
from typing import Optional, Dict
from fastapi import Request

def get_business_affinity_key(request: Request) -> Optional[str]:
    """
    纯指纹自动识别，零客户端侵入
    返回：唯一亲和绑定KEY，用于锁槽
    """
    headers = request.headers

    # 优先级1：DSH 规则引擎（最精准）
    if "x-deepseek-harness-user-id" in headers:
        uid = headers["x-deepseek-harness-user-id"]
        return f"dsh_rule_{uid}"

    # 优先级2：WebUI 会话级绑定
    if "X-Conversation-Id" in headers:
        cid = headers["X-Conversation-Id"]
        return f"webui_{cid}"

    # 优先级3：Trae Workhertz 独家特征（绝对不撞车）
    if headers.get("x-model-provider") == "custom_openai_compatible":
        return "trae_global"

    # 优先级4：DSH 主Agent
    ua = headers.get("user-agent", "")
    has_stainless = any(k.lower().startswith("x-stainless") for k in headers.keys())
    if "deepseek-harness" in ua and has_stainless:
        return "dsh_agent_global"

    # 无匹配 = 普通未知请求，走轮询
    return None
```

4. 不存在 → 分配空闲槽并永久绑定
5. **槽忙直接 429 / 排队，绝不切换槽**
